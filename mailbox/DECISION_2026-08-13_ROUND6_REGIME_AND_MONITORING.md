# РЕШЕНИЯ РАУНДА 6: панель режима, правило размера, мониторинг

# 0. УДАЛЕНИЕ ПЛАНКИ ДОХОДНОСТИ (решение оператора)

Минимальной требуемой доходности (бывшие «12%») в системе НЕ СУЩЕСТВУЕТ
ни в каком виде: ни как порог, ни как hurdle rate, ни внутри правила
режима. Цель оператора — опережать S&P 500, поэтому линейка досье —
сравнительная: в шапку каждого досье этажа 2 добавляется строка

> ожидаемая доходность имени (сценарная поверхность)
> ПРОТИВ той же оценки для VOO/QQQ на ту же дату.

Компания, выходящая из кризиса, может дать скромную бизнес-доходность
и крупный возврат множителя — сценарная поверхность обязана показывать
обе компоненты раздельно; решение о ставке на переоценку принимает
оператор, не порог.

# 1. ПАНЕЛЬ РЕЖИМА РЫНКА — 4 голосующие оси + контекст

Принцип живучести: три оси из четырёх считаются машинно из источников
собственного контура (Cboe CSV, FRED, Tiingo); только ось ожиданий
читается глазами. Панель валидна при ≥3 голосах; иначе
REGIME_INSUFFICIENT_DATA.

| Ось | +1 | −1 | Источник (проверен 12.08) | Запасной |
|---|---|---|---|---|
| Ожидания прибыли | пересмотры вверх преобладают | вниз преобладают | MacroMicro Citi ERI (беспл. регистрация) | FactSet Earnings Insight PDF (беспл.) |
| Волатильность | VIX < своей 50-дневной | VIX > 50-дневной | Cboe VIX_History.csv ✅ машинно | страница Cboe ✅ |
| Ширина рынка | RSP/SPY выше своей 50-дневной | ниже | расчёт из Tiingo ✅ свой контур | Investing.com «S&P 500 above 200-day» |
| Кредит | HY OAS ≤ уровня 20 торг. дней назад | выше | FRED BAMLH0A0HYM2 ✅ машинно | — |

Контекст (НЕ голосует): CNN Fear & Greed ✅ — плитка + метка GREED при
значении ≥75. Причина нулевого веса — двойной счёт: F&G сам состоит из
VIX, ширины, put/call и мусорных облигаций (аргумент ChatGPT принят).
Метка VOL_STRESS: VIX > VIX3M (страница термструктуры Cboe ✅; при
машинной доступности VIX3M CSV — считать скриптом).

TradingView и страница Yardeni «Earnings Revisions» ИСКЛЮЧЕНЫ из
инструкций: первая не открывается у оператора, вторая — адрес умер
(проверено глазами 12.08).

Голосование: R = сумма валидных голосов / их число.
R ≥ +0.5 → RISK_ON; −0.5 < R < +0.5 → MIXED; R ≤ −0.5 → RISK_OFF.
Конфликты решает арифметика; ручной арбитраж и «переубеждение» осей
запрещены (голос = NA только при реальной недоступности источника).

# 2. ПРАВИЛО РАЗМЕРА ПОЗИЦИИ — вариант (а), синтез двух рецензентов

Режим НЕ трогает: оценку, множители, маржу, ставку, вердикт этажа 2.
Режим НЕ является вето: при согласии обоих этажей покупка разрешена
в любом режиме. Режим ограничивает ТОЛЬКО максимальный размер первого
транша от стандартного стартового размера (стандарт определяется
портфельной политикой оператора отдельно):

| Режим | Макс. первый транш |
|---|---|
| RISK_ON | 1.00× |
| RISK_ON + GREED | 0.50× (осторожность позднего цикла — AI Studio) |
| MIXED | 0.75× |
| RISK_OFF | 0.50× (защита от ножей — ChatGPT) |
| RISK_OFF + VOL_STRESS | 0.25× (в панике покупать можно, малым шагом) |

Донабор — только на очередном еженедельном обзоре, по множителю
текущего режима. Панель читается 1 раз в неделю в фиксированное время;
внутри недели режим не пересматривается. Правила панели/размера
меняются только на квартальной дате пересмотра с лагом 4 недели;
отступление в моменте — только как задокументированный override
в журнале, не как правка правила.

# 3. ПРАВИЛО ТРЁХ ДНЕЙ (AI Studio, принято)

После провального отчёта (miss / снижение прогноза) запуск досье
этажа 2 по имени ЗАПРЕЩЁН в течение 3 торговых дней: консенсус ещё
не обновлён, расчёт будет на протухших ожиданиях.

# 4. МОНИТОРИНГ WATCHLIST — стек (все компоненты проверены)

| Поле | Инструмент | Частота | Цена |
|---|---|---|---|
| Факты (рост, маржа, EPS↔FCF, акции, долг, сторожа-флаги, RS к VOO/QQQ, просадка) | своя карточка из PostgreSQL+Tiingo | еженедельно, автоматически | 0 |
| Алерты цена/%/объём | IBKR ✅ (алерты с email проверены) | событийно | 0 |
| Пересмотры/консенсус/сюрпризы | Zacks detailed estimates ✅ | только топ-3–5 имён, глазами | 0 |
| Short float | Finviz ✅ | еженедельно | 0 |
| Даты отчётов, поле days_to_earnings | Koyfin Free ✅ / IBKR | еженедельно | 0 |
| Материальные филинги | SEC RSS ✅ | событийно | 0 |
| Реакция цены на отчёт vs QQQ | считается из Tiingo | после отчёта | 0 |

Обязательные траты: 0. Единственный будущий платный кандидат —
Koyfin Plus $39/мес, и только если ручной просмотр ожиданий перестанет
влезать в регламент (§5) два месяца подряд. Убраны из процесса: целевые
цены аналитиков, RSI/MACD, поток новостей (только материальные события).

# 5. ЕЖЕНЕДЕЛЬНЫЙ РЕГЛАМЕНТ (30–45 минут, фиксированное время)

1. [5 мин] Панель: 4 оси + F&G → R → режим → множитель размера → журнал.
2. [10 мин] Карточка фактов по 34: сортировка по ИЗМЕНЕНИЯМ с прошлой
   недели (новый флаг, скачок RS, просадка/отскок, близкий отчёт,
   филинг). Отобрать ≤5 имён.
3. [10 мин] Ожидания по топ-3–5: Zacks (пересмотры 30/60 дней, сюрприз,
   дата отчёта). Пересмотры вниз → WATCH; вверх → кандидат на этаж 2.
4. [10 мин] События по кандидатам: первоисточник (филинг/IR), не заголовок.
5. [5 мин] Статусы (IGNORE/WATCH/NOMINATE_FLOOR2; ≤2 номинаций в неделю)
   + запись в журнал: режим, кто эскалирован, почему, почему НЕ куплено
   соблазнительное.

Событийная ветка (алерт IBKR): что сработало → плановое ли событие →
первоисточник → движение против QQQ → изменились ли ожидания → задет ли
тезис. Нет → только запись. Да + этаж 1 позитивен → NOMINATE_FLOOR2.
Плюс правило трёх дней (§3).

# 6. РЕЗУЛЬТАТЫ ПРОВЕРКИ ИСТОЧНИКОВ 2026-08-12 (фиксация)

Машинно-критичный контур: SEC companyfacts/companyconcept/RSS ✅,
FRED DGS10 (история 64 года) ✅, FRED HY OAS ✅ (публичное окно
подтверждено = 3 года: 2023-08→2026-08), Cboe VIX CSV (с 1990) ✅,
IBKR (котировки+алерты, live) ✅, Tiingo — доказан продом,
edgartools 5.48.0 ≥ 5.39.1 ✅ (версию запинить).
Глазами: Zacks ✅, CNN ✅, Finviz ✅, Koyfin ✅; MacroMicro — требует
бесплатной регистрации (проверить после неё); TradingView — недоступен
оператору, исключён; Yardeni revisions — адрес мёртв (404), исключён,
запасной — FactSet Earnings Insight.

**Находка прогона:** SEC отдаёт по META поле dei (473 тега) — при том,
что проверка №1 отказывала «dei отсутствует в источнике». Расхождение
означает: либо SEC дозаполнил данные, либо дефект в НАШЕМ снапшоте/
загрузчике. В эксперимент добавляется задача META-RELOAD: свежий забор
companyfacts META → сверка с базой → диагноз одной страницей. Это
диагностика, не стройка; разрешена затвором.
