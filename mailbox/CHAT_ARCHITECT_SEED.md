## 4. СВОД ПРАВИЛ — главное наследство проекта

Каждое правило куплено конкретным дефектом. Их около тридцати; здесь — несущие.

**О данных и числах**
- Ноль вместо неизвестного запрещён. Отсутствие называется отсутствием и объясняет причину.
- Различаются три состояния: отсутствует / отказано как недостоверному / не запрашивалось.
- Базис едет с числом: у каждой величины видно, откуда она и в чём измерена. Сравнение
  величин разных базисов запрещено.
- Арифметику считает код, суждения выносит модель. Любое денежное число, которое модель
  может написать свободно, — дефект.
- Диагноз ставится по сырому источнику, а не по отчёту о нём.
- Числа о собственной работе берутся с выхода инструментов, не из памяти и не из документов.

**О проверках**
- Отказ проверки не равен проходу: SKIP, NOT_EXEC, пропущенный тест, ошибка загрузчика —
  не зелёный.
- Проверка обязана доказывать применимость: для каждой существует намеренная поломка,
  которая обязана её покраснить. Пустой пин опаснее отсутствующего — он занимает место.
- Пин охраняет **свойство**, а не форму. Пин на имя переменной запрещает правку кода,
  а не дефект.
- Условие вокруг проверки — тот же пропуск, только неотчитывающийся.
- Измерение инструментом, который сам не проверен, есть утверждение о приборе, а не о мире.

**О публикации**
- Пин на содержимое поверхности не проверяет её доставку. Каждой поверхности — два
  независимых пина: содержимое верно и поверхность соединена с получателем.
- Класс «произведено, но не опубликовано» встречался **пять раз**. Проекция, перечисляющая
  поля поимённо, убивает по умолчанию любое новое поле выше по течению.
- Исправление одной поверхности из двух — встречалось трижды.
- Проза о числах строится из тех же чисел, а не хранится константой.

**О процессе**
- Провенанс артефакта — часть приёмки. Работающий код неизвестного происхождения хуже
  отсутствующего: он выглядит проверенным.
- Инвариант должен быть структурным, а не в комментарии. Предупреждение в тексте
  ограничителем не является.
- Пре-регистрация фиксирует намерение и не проверяет замысел; от ошибки конструкции
  защищает только пин на свойство.
- Всякий порог носит метку происхождения: измеренная константа или провизорная
  калибровка с размером выборки.
- Различение, покрывающее два состояния из трёх, ошибается уверенно.
- Согласованность фикстуры и рендера между собой не доказывает согласованности с системой.
- Сторож, смотрящий везде, кроме места, где лежит улика, — не сторож.

## 5. СОСТОЯНИЕ НА 6 АВГУСТА 2026

### Что работает

- **Расчётное ядро** с двумя оценками (консервативная вердиктная и центральная
  справочная), обратным расчётом, самодокументируемыми параметрами.
- **Человеческая записка** по-русски: описание бизнеса, тезис, коридор оценок,
  лестница входа, катализаторы с ценой в долларах, что отслеживать, как посчитано, словарь.
- **Автоматизация в GitHub**: робот-тестировщик гоняет весь сьют и каталог мутаций в
  чистой среде при каждой заливке; агент-аудитор разбирает каждую заявку; агент-исполнитель
  делает правки по карточке и открывает заявку.
- **Первая задача прошла полный цикл 6 августа** (заявка #13): карточка → агент → заявка
  → аудит → тесты → слияние, без единой пересылки файла.
- **Внешняя память**: два публичных репозитория, обмен через `mailbox/`.

### Что не работает

- **Качественный слой полумёртв.** Поисковая модель возвращает обзорные статьи, а не
  проверяемые факты. Измерено: на прогоне ORCL один содержательный раздел из четырнадцати.
  Причина установлена по сырым ответам: часть запрашиваемого не существует в открытом вебе.
- **Валидационная матрица пройдена частично**: MA, META, NFLX, ORCL — четыре однотипных
  крупных технологических компании. Не пройдены LLY, SOFI (банк), NVO (IFRS), RDDT
  (молодой эмитент).
- **Инцидент с долгом не закрыт**: корневая причина устранена, но ветка расхождения
  источников не проверена на живых данных, заражённые снимки не идентифицированы.
- **Бизнес-логика внутри n8n** — 24 узла с кодом, хранимым строками в JSON, до 58 000
  символов в строке. Измеренное следствие: агент-исполнитель потратил 37% бюджета шагов
  на попытки прочитать этот файл и не смог.

## 6. ОЧЕРЕДЬ

**Первое: разбор критики внешних аудиторов.** Аудиторский пакет собран (15 документов
в `external_audit_package/`) и роздан. Оператор прочитал первые отзывы: **вопросов много,
возможно потребуется существенно менять архитектуру.**

Решение оператора от 6 августа: **валидационную матрицу отложить до разбора аудита** —
если архитектура изменится, прогоны на старой системе окажутся потраченными деньгами.
Архитектор возразил и принял возражение оператора с уточнением: аудит может ударить
и в методику (формулы, отраслевые развилки), и в инженерию (где живёт код). Если только
в инженерию — часть матрицы всё равно понадобится.

**Правило приёма замечаний:** замечание становится задачей **только после того, как
воспроизведено на артефакте**. Внешний критик уже ошибался уверенно (советовал ставить
пакет по несуществующему пути). Поток критики от трёх ИИ без фильтра — генератор работы,
а не находок.

**Второе: решение по архитектуре** — переезд логики из n8n в Python-пакет. Согласован
**второй путь**: постепенно, начиная с узла записки, каждый шаг проверяемый. Влияние
на инфраструктуру разобрано: Railway почти не меняется, n8n худеет, агент получает
читаемые файлы. Главный риск — сосуществование двух копий логики; защита — переключение
одним изменением, без переходного периода.

**Третье: валидационная матрица** — LLY, SOFI, NVO, RDDT, по паре прогонов, около $6.
С пре-регистрацией ожидаемого класса поведения до каждого прогона.

**Четвёртое: линия БАЗЫ** — DDL v1.11, разложение флага качества снимка, засев списка
наблюдения, импорт позиций, квартальные данные (без них алерты невозможны).

**Пятое: заливка 34 имён и выход в рабочий режим.**

## 8. ПРОМАХИ ПРЕДЫДУЩЕГО АРХИТЕКТОРА

Раздел написан намеренно: преемник должен знать не только правила, но и то, как их
нарушал предшественник.

**Правки по гипотезе вместо чтения источника.** Дважды строил версии о причине сбоя,
не открыв лог того шага, где рождается результат. Настоящая причина оба раза лежала
в логе прямым текстом. Это правило 3 проекта, нарушенное его же автором.

**Два рычага одновременно.** При отладке агента расширил права и снял ограничение вывода
одним изменением — получил разнос на 8800 строк и не смог понять, что именно виновато.

**Текстовый запрет вместо структурного.** Написал агенту в инструкции «не читай эти
каталоги» и дал широкие права. Агент прочитал. Граница должна быть в правах, а не в тексте.

**Показал устаревшую копию файла.** Правил рабочую версию, а оператору выложил старую —
класс «произведено, не опубликовано», на этот раз у архитектора.

**Ошибка в постановке задачи агенту.** Велел дописать строку в файл, которого не
существует, не проверив. Агент проверил и остановился — то есть исполнил правило лучше
автора правила.

**Вывод для преемника:** правила, добытые в одном слое, не переносятся автоматически
в другой. При выходе в новую область (инфраструктура, агенты, чужие инструменты) первым
делом спрашивай себя, применяешь ли ты к ней собственную дисциплину.

## 10. ПРАВИЛА ТВОЕЙ СОБСТВЕННОЙ РАБОТЫ

- **Приёмка только по сырому**: скачай дерево, запусти проверки сам. Доклад исполнителя
  не заменяет артефакт. За неделю это трижды поймало расхождение доклада с кодом.
- **Длинное — файлом** в `mailbox/`, в чат — сводка по форме: что изменилось / что
  дальше / что нужно от оператора.
- **Числа о себе не производить.** Не заявлять о собственной загрузке или усталости —
  этого измерения у тебя нет. Ошибки докладывать классом.
- **Ротация**: граница по завершённому артефакту. Аварийный сигнал — две ошибки одного
  класса, пойманные не тобой, внутри одной задачи. Судья — оператор.
- **Задачи агенту дробить мелко**: одна карточка — один дефект. Задача «правка + два
  пина + мутация» упёрлась в потолок 40 шагов; пришлось поднимать до 80.
