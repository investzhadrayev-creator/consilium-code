## 4. Находки по ходу
1. edgartools `get_filings(form=["10-K"])` возвращает и 10-K/A. Реальный случай: GOOG 10-K/A от 2019-02-06 (0001193125-19-028757), только экзибит 23, без XBRL. Выбор формы делает адаптер по точному совпадению (мутация k2-04).
2. Класс A diluted уже включает if-converted класс B: META FY2021 consolidated = Class A = 2 859 000 000 при Class B = 432 000 000. Сумма классов дала бы двойной счёт 432M. Поэтому классы публикуются поштучно, итог отказан именованно `MULTI_CLASS_NOT_SUMMED`.
3. Для META прежний fast path подставлял в `shares_current` средневзвешенное diluted (флаг `shares_current_proxied`). Адаптер этот прокси отбрасывает (`shares_current_proxy_rejected`) и возвращает `None` + отказ + cover-счёт по классам.
4. Не герметичен был сам `edgar_facts()`: цепочки `_shares_current` и `_detect_confirmed_splits` ходят в companyconcept по сети, а ошибки глотаются (`except Exception`). Для goldens записаны все эти ответы, включая 404 (GOOG и META: dei/EntityCommonStockSharesOutstanding). Тест ловит любое обращение к сети.

## 5. Что осталось незакрытым
- Адаптер **не подключён** к `app.py` / маршрутам / workflow: задача требует адаптер и goldens, подключение отдельным решением.
- GOOG 2022-10-12: `shares_current` = 13 078 000 000 (баланс на 2022-06-30, после сплита), а годовые diluted по классам поданы до сплита (10-K от 2022-02-02). Адаптер эту базисную разницу **не сверяет** (итога по классам нет, сравнивать не с чем); `confirmed_splits_none` из `edgar_facts()` на эту дату пройден как есть. Требует решения о методе.
- Итог по классам (META cover, GOOG diluted) не вычисляется вообще: это решение о методе (голосующие vs экономические классы), не арифметика.
- `gross_profit` у META и GOOG отсутствует во всех датах (`_missing`); адаптер не классифицирует это как VALID_MISSING, т.к. это не проверялось на уровне filing.
- Поддерживаются только формы 10-K / 10-Q; 10-K/A с полным XBRL (рестейтмент) намеренно не читаются.
- Зависимость `edgartools` тянет транзитивные пакеты (httpx, pyarrow и др.) в деплой Railway; размер образа не измерялся.
- `LiveLoader` проверен вручную один раз (см. выше), автоматического теста с сетью нет по правилу «сьют офлайн».
- Даты проверки №1 (5 штук) совпадают с `POSITIVE_CONTROL_DATES`/`NEGATIVE_CONTROL_DATES` в `tools/historical_run.py` (сам скрипт не запускался) и подтверждены оператором в карточке.
