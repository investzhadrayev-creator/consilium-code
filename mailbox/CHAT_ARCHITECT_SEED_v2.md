## 1. ПРОЕКТ И ЕГО ТЕКУЩАЯ ФОРМА

Частный инвестор (Аскар, Астана, GMT+5, Windows/PowerShell) строит систему анализа
акций. **Финальная форма после трёх раундов внешнего рецензирования (принята):**
*auditable expectations-ranking and validation harness* — проверяемая машина
ранжирования ожиданий, а не «свой движок оценки».

Выход: рейтинг имён по подразумеваемой доходности с разложением роста, сторожами
режимов и именованными отказами. Решатель — заменяемая коммодити; ценность —
в контроле данных, отказах, сторожах и честной валидации.

**Своё:** as-of реконструкция «на дату», fail-closed семантика, разложение
рост/маржа/акции, сторожа режимов, пре-регистрация и аудит-трейл.
**Взять:** `edgartools` (сантехника EDGAR), `implied-expectations==0.1.0`
(только решатель, как независимый оракул для дифф-тестов — его загрузчик заражён
дефолтами tax=21%/ROIC=20%/debt=0), BoothCheck (внешний comparator), Дамодаран
(эталоны). **Прекратить строить:** свой generic reverse-DCF, свой generic
EDGAR-клиент, мультиагентный консенсус оценки, новостной/качественный балл.

## 5. ДВЕ НАХОДКИ ОПЕРАТОРА — ГЛАВНАЯ РАБОТА СЛЕДУЮЩЕЙ ЭПОХИ

1. **Порог 12% как критерий покупки не имеет опоры** — это личное предпочтение
   доходности, а не свойство актива; ставка сдвигает всю шкалу и на порядок имён
   почти не влияет. Вердикты убрать, оставить ранжирование.
2. **Конструкция структурно слепа к возврату мультипликатора.** Терминальный
   множитель = `min(историческая медиана, payout/(k_exit−g))` — сжатие вниз
   учитывается, восстановление вверх исключено по построению. Компания выходит
   из кризиса, множитель возвращается к норме, цена растёт при слабом росте
   прибыли — система этого не увидит. Улика: на ковидном дне 2020 система не нашла
   ни одной покупки, хотя последующая доходность пришла в основном от переоценки.

Обе отправлены рецензентам (`ROUND4_2026-08-11_TEST1_AND_METHOD_REVISION.md`).
**Их ответы оператор принесёт в новый чат — с них и начинается работа.**

## 6. ПРАВИЛА, КУПЛЕННЫЕ ОШИБКАМИ (соблюдать)

**Работа с роботами.** Термины: «карточка» (Issue), «правка» (PR). Задания — только
через карточки с явным именем ветки; комментарий в правке будит робота вслепую.
Один будящий @claude-комментарий = одно исполнение. «Re-run failed jobs» даёт
пустой зелёный — запрещён. Зелёный без прочитанного вердикта аудита не принимается.
Из двух правок на один файл первой сливается меньшая; правки на один файл
не запускать параллельно.

**Против бесконечной полировки.** Замечания аудита со статусом «до мержа» — чинить;
чисто советные — в реестр и сливать. Если очередной аудит приносит только советные —
добро на слияние властью архитектора.

**Проверка.** Перед инструкцией — проверить живое состояние GitHub; после «сделал» —
проверить по артефакту, не по тексту. Проверка деплоя — не `/health` (несёт версию,
но не состав маршрутов), а новый маршрут. Класс «вывод по неполному источнику» —
самый частый; встречался у передающей эпохи трижды.

**Пороги и константы.** Никогда «из головы». Калибровать на данных с показанным
распределением и разделением (эталон: порог устаревания 1095 дней внутри пустого
коридора 723–2521 дней по 170 ногам архива). Порог, назначенный без калибровки,
уже стоил проекту провала пилота.

**Отказы.** Отказ вместо подстановки; «неизвестно» никогда не 0/1.0/дефолт.
Массовый однотипный отказ на реальном прогоне = баг инструмента, не данных.
Фикстуры обязаны совпадать с форматом реальных данных (класс «фикстура не как
жизнь» стоил прогона 175/175 REFUSED).

**PowerShell/Windows.** URI обязательно с `https://` (иначе POST превращается в GET →
405). Скрипты — ASCII + BOM, без кириллицы. Проверки на подстроку по всему телу
ответа запрещены (совпадение «429» внутри котировки стоило двух суток).

**Tiingo Starter:** 50 запросов/час (окно скользящее!), 1000/день, 2 GB/мес.
Безопасный темп для тяжёлых диапазонных запросов — пауза 150 сек.

## 8. ЧЕСТНАЯ КАРТИНА ДЛЯ ТЕБЯ

Неделя работы дала: работающий as-of стенд с живой сверкой (NVDA 23.03.2020,
P/E 31.92 против ручного 32.08), пройденный затвор-пилот, честно опубликованный
провал второго пилота, конвейер с десятками циклов карточка→правка→аудит→слияние,
шесть дефектов инструмента, пойманных проверками до публикации чисел, и
несостоявшуюся проверку №1.

Главный урок эпохи: **самой дорогой ошибкой была не методика, а планирование
данных** — универсум для исторического теста взят из тематического списка
оператора без проверки, сколько имён существовало на 2018 год. Рецензенты трижды
рекомендовали сменить универсум; исполнено не было. Проверяй существование данных
до заморозки протокола, а не после прогона.
