# РАУНД 7 — РЕЦЕНЗИЯ CHATGPT

**Позиция: перезапуск поддерживаю.** Прежняя схема зависела от доступности оператора и фактически остановилась. Автоматизация устраняет правильное узкое место. Однако нельзя заменять человеческую дисциплину неконтролируемой автономией архитектора и бота.

## В7.1 — Definition of Done

**Кандидат принимаю с четырьмя поправками.**

1. **Этаж 1:** четыре последовательных недельных выпуска по watchlist, покрытие обязательных полей ≥95%, provenance, as-of, именованные missing/refusal. Панель ≥3 валидных голосов, без подстановок.
2. **Этаж 2:** воспроизводимый конвейер запроса, медианное машинное время ≤2 часов. Обязательны сценарная поверхность против VOO/QQQ, сторожа, GAAP/non-GAAP basis check, условия опровержения тезиса.
3. **Три досье, не два:** NFLX-FY2019 плюс два живых имени. Это сохраняет решение раунда 5.
4. **Регрессия:** MU/INTC/META/GOOG проходят golden-тесты; NFLX даёт RED на заранее зарегистрированной версии сторожа.
5. **Журнал:** решения оператора фиксируются до исхода, автоматические расчёты отделены от человеческих инвестиционных решений.
6. **Операционная устойчивость:** независимый валидатор артефактов, сигнализация об ошибках и доказанный повторный запуск после сбоя.

**Вычеркнуть:** обязательное ежедневное письмо в дни работы как критерий готовности, постоянный ручной ERI/Zacks, инвестиционную результативность как критерий технической приёмки.

**После прохождения гейта — объявить проект FINISHED.** Дальнейшие улучшения только по отдельным решениям, не бесконечный backlog.

## В7.2 — Риски автономного исполнения

**Главный риск — self-certification:** одна автоматизированная цепочка производит данные, меняет правила и подтверждает собственную корректность. История ложнозелёных тестов Consilium делает риск не теоретическим.

Минимальный контроль:

1. `main` защищён GitHub ruleset. Код и правила меняются через PR; критические файлы, включая workflows, сторожей и правила панели, требуют явного одобрения оператора. Нет автономного обхода защиты.
2. Бот публикует данные через отдельные PR, автоматически сливаемые после независимой CI-валидации. Только разрешённые пути `journal/` и `Reports/`; GitHub token permissions сами по себе не обеспечивают ограничение по каталогам.
3. CI проверяет неизменность существующих записей, уникальность ключей, схемы, даты, источники, количество реально выполненных тестов. `NOT_RUN` и `UNKNOWN` никогда не становятся `PASS`.
4. Еженедельный дайджест: коммиты, пропуски, ошибки, расходы API, изменения правил. Внешняя копия контрольного хеша журнала защищает от незаметной перезаписи Git-истории.
5. Ограниченные права Actions и секретов, pin зависимостей, лимиты времени и затрат. Никакого исполнения недоверенного кода с доступом к секретам.

**Архитектор предлагает и проверяет; независимые тесты принимают данные; оператор утверждает изменения методологии.** Ни одной обязательной еженедельной операции для человека.

## В7.3 — Новый экспериментальный гейт

**Принимаю четыре АВТОНЕДЕЛИ, но не четыре зелёные надписи.**

Условия PASS:

- Четыре последовательных запланированных цикла: карточка и панель опубликованы в срок, валидатор подтвердил содержимое, покрытие ≥95%, ноль выдуманных значений.
- Минимум три полных досье: NFLX плюс два живых. Для двух живых разрешены заранее зарегистрированные машинные тестовые запросы, без участия оператора.
- NFLX-FY2019 → RED без подгонки порога после просмотра экзамена.
- META/GOOG и остальные goldens проходят.
- Ни одной ретроспективной правки правил.
- Ноль обязательных минут оператора для штатного функционирования.

Разделить `SOURCE_UNAVAILABLE`, `PIPELINE_FAILED` и `VALID_MISSING`. Отсутствие источника не разрешает подстановку. Недостоверный выпуск не засчитывается, даже если workflow завершился успешно.

При провале — автоматическая остановка соответствующей ветки, уведомление и диагностика. Не уничтожать готовый инструмент целиком из-за временной недоступности внешнего API.

Итоговое решение GO/NO-GO оператор принимает однократно после накопления доказательств. Календарного дедлайна нет.

## В7.5 — Канал рецензента

### (а) Ручной батч раз в месяц

Один пакет: ссылка на immutable commit SHA; список принятых после прошлого раунда решений; конкретные изменения; измеренные результаты тестов; дефекты и разногласия; максимум 3–5 вопросов, требующих внешнего суждения.

Не пересылать весь архив. Достаточно манифеста точных файлов и указания, что считается неизменяемым решением. Ответ — `ACCEPT / REJECT / CONDITIONAL`, причина и проверяемое условие.

### (б) OpenAI API вместо ручного канала

**Согласен на автоматизацию функции рецензента, но не на объявление API-модели эквивалентом данного экземпляра ChatGPT.** Поведение зависит от версии модели, инструкций и переданного контекста. Совпадение провайдера не гарантирует совпадения выводов.

Предлагаемый протокол:

1. OpenAI Responses API; доступная API-модель экспертного класса (например, `gpt-6-sol`, после проверки доступа), закреплённая конкретной версией/snapshot. Не использовать плавающий alias без контроля изменений.
2. Температура `0` там, где поддерживается; иначе штатная конфигурация reasoning-модели. Лимит генерации 6–8 тыс. токенов, явная инструкция краткого ответа.
3. Передавать полное ТЗ раунда, манифест входных файлов с SHA, принятые правила и конкретные результаты проверок. Никакой молчаливой опоры на память предыдущего чата.
4. Сохранять: точный model ID, параметры, хеши входов, текст ответа, статус, usage, стоимость, timestamp. Итог — новый append-only `mailbox/ROUND*_REVIEW_CHATGPT_API.md`.
5. Разделить авторство и аудит: рецензент не имеет полномочий менять код, правила или утверждать собственные рекомендации.
6. При тайм-ауте/API-ошибке — ограниченные повторы с backoff; затем `REVIEW_UNAVAILABLE`, уведомление. Никакого фиктивного согласия и молчаливой подмены модели.
7. Изменение модели — отдельный мини-regression на старых спорных кейсах перед использованием новой версии.

Первый автоматический раунд провести параллельно с ручным ответом и сравнить существенные решения. После успешной сверки ручной канал оставить только для споров, методологических изменений и расхождений между рецензентами.

**Итог:** Consilium должен стать законченным, воспроизводимым инструментом инвестиционной дисциплины, а не постоянно развивающейся исследовательской платформой. Автономность допустима для производства фактов, но не для изменения правил игры и принятия инвестиционных решений.
