## 2. АРХИТЕКТУРА, СЛОЖИВШАЯСЯ К ЭТОЙ ЭПОХЕ

**Две линзы.** Вердиктная — min окон роста, потолок множителя `min(median_5y, median_10y, 30)`,
фейд к 4%. Центральная — медиана годовых приростов, множитель без потолка; **advisory, не решает
ничего**, пины запрещают её чтение вне рендеров. Разрыв раскладывается по факторам
(`gap_decomposition`); проза о разрыве **строится из этого поля**, а не хранится константой.

**Три ассемблера.** `Assemble Report` (машинный, английский), `Assemble Brief` (записка,
русский; `SPEC_SECTIONS` пинит состав и порядок), `Assemble Core-V`.
**Выход прогона = ПАРА документов**, доставка обоих обязательна.

**FACT_PACK: четыре тематических вызова ЦЕПЬЮ** (`fin → legal → compete → news → Merge`).
Веер не годится — n8n не ждёт, слияние срабатывает по первой ветке. Слияние тонкое: коллизия
раздела — явный отказ, отказ вызова — `SOURCE_CALL_FAILED`, незапрошенные разделы отбрасываются.

**Гейт сущности** `Verify FACT_PACK Entity` между Stage 1 и девятью потребителями: сверка CIK из
эха `RESOLVED_ENTITY` с GROUND_TRUTH, жёсткий отказ до всякого суждения.

**Класс для реестра:** «ноль вместо неизвестного» на балансовом поле. Сторож существовал с

(`divergence.total_debt`).

### 3.1c. ПОВТОРЯЮЩИЙСЯ КЛАСС: «произведено, не опубликовано»

Четыре случая за шесть чейнджсетов: поле в `base_inp` вместо RESULT; контрактные правки,
посчитанные и не записанные в ноду; проекция peer-строк, перечисляющая поля поимённо и
выбрасывающая всё новое; та же форма в проекции сценариев (`label_ru`). **Универсальный пин
доезда — обязательный пункт следующего инфраструктурного чейнджсета** (решение архитектора).
Правило: проверка «правка применилась» и проверка «правка доехала» — разные проверки.

## 5. РЕЕСТР ПРАВИЛ, ДОБЫТЫХ ЭТОЙ ЭПОХОЙ

1. **Диагноз только по сырому источнику.** У отчёта много поверхностей, и они не равноправны.
   Три раза подряд ложная поверхность стоила цикла: обрезанная ячейка, разметка Telegram,
   проза арбитра.
2. **Значение, выглядящее измерением.** `.slice(0,140)` дал `0` вместо `0.0182`; `_not run_`
   с именем модели рядом; счёт кейсов глазами; заголовок над мёртвыми подразделами.
   Лечится тем, что **число производит инструмент, а не глаз**.
3. **Пин содержимого ≠ пин доставки.** Каждой поверхности два независимых пина: содержимое верно
   и поверхность соединена с получателем. Первый зелен ровно тогда, когда второй нарушен.
4. **Список поверхностей проверяется грепом по СВЯЗЯМ, не по наличию нод.** Нода без исходящей
   связи — поверхность, которой нет.
5. **Фикстура, согласованная сама с собой, ничего не доказывает.** Три дефекта имели эту форму:
   пин утверждал поле, которого система не производит.
6. **Пин, проверяющий форму или имя переменной, запрещает правку, а не дефект.**
7. **Пре-регистрация обязана включать исход «без изменений» с причиной** и предсказывать
   ПОВЕДЕНИЕ СИСТЕМЫ при известном свойстве данных; предсказание самого свойства — гипотеза о мире.
8. **Различение, покрывающее два состояния из трёх, ошибается уверенно.** «Недоступный источник»
   против «нет фактов» не знало третьего: «ещё не исполнено».
9. **`SKIP` в каталоге мутаций — отказ проверки**, не нейтральный исход.
10. **Проза о числах генерируется из тех же полей, что числа рядом.** Объяснение, верное на одном
    имени и напечатанное на всех, есть ложь с правдоподобной историей.
11. **Незапрошенное не должно выглядеть ненайденным**; недоступный источник — инженерное событие,
    отсутствие фактов — факт о мире.
12. **RESULT — снимок эпохи своего конвейера.**
13. **Решение, записанное в точке использования, невидимо для поиска по инфраструктуре.**
14. **Порог и определение метрики — одна сущность.** Смена знаменателя молча обнуляет калибровку.
15. **Ловушка в инструменте проверки закрывается устранением, не комментарием:** задокументированная
    ловушка выглядит закрытой и притягивает новые нарушения.

## 6. ИНТЕРФЕЙС ОПЕРАТОРА

Аскар — оператор, все живые действия через него. Архитектор общается через оператора.

* инструкции пошаговые: что СНАЧАЛА, что ПОТОМ, КОМУ отправить, КАКИЕ файлы приложить;
* каждый шаг — одно действие, без жаргона и внутренних имён полей;
* сообщения архитектору — готовым текстом для копирования целиком;
* каждый созданный файл сопровождается строкой: что это и что с ним делать;
* **HANDOFF — один накопительный файл с неизменным именем**, новые секции продолжают буквенный
  ряд (A..Z, AA..ZZ, AAA...); отдельные файлы под каждый разбор не создаются;
* **артефакт, для которого есть сборщик, собирается только сборщиком** (`tools/build_handoff.py`);
* ответы на русском, финансовые термины по-английски.

**Критика авторизована:** жёсткий независимый критик пайплайна, который сам же помогал строить;
защищать вложенное не требуется. Ограничения: реальные деньги, ограниченный бюджет отладки.
