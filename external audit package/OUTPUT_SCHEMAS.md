## 2. Как выполняются требования аудита к денежным полям

Требование: каждое денежное поле должно нести валюту, единицу, базис, период,
источник, преобразование, уверенность, причину отсутствия, версию расчёта.

| Требование | Состояние |
|---|---|
| Валюта | **НЕТ.** Подразумевается USD, нигде не указана |
| Единица | частично: имена полей содержат `_pct`, `_per_share`, `_usd` не используется |
| Базис | **есть в ключевых местах**: `computed_on`, `delta_vs`, `basis` у якорей, `peer_multiple.basis`, `pe_at_todays_price` — базис вшит в имя поля |
| Период | частично: `three_year_table` несёт конец фискального года; у остальных величин периода нет |
| Источник | частично: `_field_sources` внутри слоя данных, в итоговый снимок выводится не полностью |
| Преобразование | **НЕТ** как отдельного поля; восстанавливается по коду |
| Уверенность | **НЕТ** |
| Причина отсутствия | **есть**: флаги семейств `*_absent`, `*_refused_*`, `SINGLE_LEG_RUN`, `CONTRACT_DEFECT_*` |
| Версия расчёта | **есть** через версию сборки, но в самом снимке присутствует не всегда — дефект, обнаруженный при разборе отчётов |

**Вывод:** требование выполнено примерно наполовину и несистематически. Базис
и причина отсутствия проработаны хорошо (это следствие конкретных дефектов), валюта
и уверенность отсутствуют полностью.

## 3. Состояния прогона

| Состояние | Признак в снимке |
|---|---|
| Нормальный | `run_complete: true`, `iv_computable: true`, `dual_basis` — объект |
| Одноногий | `dual_basis: null` + флаг `SINGLE_LEG_RUN` с причиной |
| Модель неприменима (Category-F) | `iv_computable: false`, уход на ветку Core-V |
| Отказ по личности эмитента | прогон не доходит до расчёта |
| Отказ разбора вердикта | прогон уходит в доработку, снимок не пишется |

**Отдельные схемы для состояний «неприменимо» и «заблокировано» не определены** —
различение идёт полями, а не отдельными контрактами.

---

## 4. Версионирование

**Правил версионирования схемы не существует.** Поля добавляются по мере необходимости;
единственная защита — пин, требующий, чтобы каждое поле, читаемое поверхностью
публикации, существовало в реально производимой структуре.

Следствие, наблюдавшееся неоднократно: поверхность читала поле, которого система не
производит, и печатала умолчание. Три таких случая за одну неделю, один из них — на
строке цены входа.

сохранялись.
