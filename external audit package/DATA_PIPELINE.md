## 1. Маршрут

```
SEC EDGAR (XBRL API)
  → отбор фактов по тегам и периодам        edgar_facts.py
  → проверка целостности ряда (провенанс)   edgar_facts.py
  → нормализация в ряды по фискальным годам
  → сверка альтернативных источников (долг)
  → производные метрики (CAGR, медианы, дилюция)
  → расчёт стоимости                        ivc_lib.py
```

Параллельно: цены и рыночные величины (Tiingo, макро-источник) → `market_facts.py`,
`pricing.py`.

## 2. Отбор фактов

**Разрешённые источники периода** заданы **положительным списком** (`fy_source`),
а не списком исключений. Это принципиальное решение: значение, полученное выводом
из даты, не проходит не потому, что запрещено, а потому что его нет среди годных.

**Правило одного тега на ряд.** Ряд обязан быть собран одним тегом. Смена тега внутри
ряда — дефект провенанса, а не повод «сшить» значения.

**Как это правило появилось.** У Mastercard за 2018–2021 годы использовался тег валовой
выручки вместо чистой; в результате темп роста вышел 6.78% вместо 16.47%. Дефект жил
незамеченным и искажал вердикт. Обнаружен по разрыву в ряду маржи (×1.59).

**Оконное покрытие.** Сплошной ряд требуется для **окон, входящих в якорь роста**
(3 и 5 лет), а не для всей истории. Дыра вне окон не дисквалифицирует ряд. Правило
введено после случая, когда отсутствие одного года 2015 отвергало корректный тег.

**Непрерывность провенанса.** Дефектом считается смена тега, единицы измерения, формы
отчётности или разрыв по годам. Номер подачи (accession) понижен до со-сигнала:
эмпирически 76–89% его смен — рутинные.

## 3. Что реализовано и что нет

| Требование аудита | Состояние |
|---|---|
| Выбор XBRL-контекста | по положительному списку `fy_source` |
| Дублирующиеся факты | отбор по правилу одного тега; конфликт — дефект |
| Разные единицы | смена единицы внутри ряда = дефект провенанса |
| Исправленные подачи (amended) | **НЕ РЕАЛИЗОВАНО**, понятие в коде отсутствует |
| Пересмотры отчётности (restatements) | **НЕ РЕАЛИЗОВАНО** |
| TTM (скользящие 12 месяцев) | **НЕ РЕАЛИЗОВАНО**: работа ведётся по годовым рядам; квартальные данные — веха базы, не начата |
| Различия фискальных годов | учитываются: ряды собираются по концам фискального года, в отчёте печатается конец периода каждой строки |
| Дробления акций (splits) | распознаются косвенно: `\|dilution\| > 20%` считается артефактом сплита, значение обнуляется с флагом; для дивидендного ряда сплит внутри окна отвергает ряд целиком |
| Коэффициенты ADR | **НЕ РЕАЛИЗОВАНО** |
| Смена таксономии тегов | обнаруживается как дефект провенанса |
| Несогласованные знаки | **НЕ РЕАЛИЗОВАНО** как отдельная проверка |
| Ноль против неизвестного | различаются: отсутствие даёт отказ с причиной, а не ноль |
| Провенанс | ведётся: `_field_sources`, `_flags`, `_missing` |
| Воспроизводимость старого прогона после изменения нормализации | **НЕТ.** Снимок содержит результат, но не входные сырые факты; повторить старый прогон на новом коде нельзя |

Последняя строка — существенный ответ аудитору: **система не является воспроизводимой
в строгом смысле.** Снимок фиксирует, что получилось, но не позволяет пересчитать
прошлое на изменённом коде.

## 4. Сверка источников: долг

Долг собирается тремя путями по убыванию предпочтения: полный тег; сумма компонент
(долгосрочная часть + текущая); комбинированный тег. При отсутствии всех — поле
объявляется отсутствующим.

Расхождение между путями записывается в `divergence.total_debt`.

**Известный дефект:** сторож расхождений проверял другие поля и до `divergence.total_debt`
не добирался; ветка расхождения по-прежнему не проверена на живых данных.
См. `DEBT_INCIDENT_REPORT.md`.

## 5. Производные величины

| Величина | Как считается |
|---|---|
| Темп роста (якорь) | минимум из CAGR за 3 и 5 лет по конечным точкам |
| Темп роста (справочный) | медиана годовых приростов за 5 лет; при менее чем трёх приростах — отказ, поскольку медиана по двум точкам есть среднее |
| Медианы множителя | по истории цены и прибыли, окна 5 и 10 лет |
| Дилюция | CAGR числа разводнённых акций; один знаменатель на обе ноги, тег DEI исключён |
| Дивидендный рост | по ряду объявленных дивидендов на акцию; ряд отвергается при сплите внутри окна |

## 6. Различение отсутствия

Три состояния, не сводимые друг к другу:

- **отсутствует** — данных нет у источника;
- **отказано** — данные есть, но признаны недостоверными (сплит в окне, расхождение
  источников);
- **не запрашивалось** — тема не входила в текущий вызов.

Смешение этих состояний считается дефектом. Пример из практики: маркер
«не запрашивалось», доехавший до читателя, выглядел бы как «искали и не нашли».

## 7. Схема снимка (упрощённо)

Снимок оценки, сохраняемый в PostgreSQL, содержит: идентификаторы (тикер, дата, версия
сборки), входы расчёта, результаты обеих ног, вердиктную ногу, лестницу входа, флаги,
блоки качества, учёт расходов, признаки полноты качественного слоя.

**Точная схема таблиц в этом пакете отсутствует** — она принадлежит линии базы данных,
задание выписано отдельно.

## 8. Что аудитору стоит проверить

1. §3, строка о воспроизводимости: снимки не содержат сырых входов.
2. Отсутствие понятий «исправленная подача» и «пересмотр отчётности» при работе
   с первичными данными SEC.
3. Отсутствие TTM при заявленной цели квартальных алертов.
4. Косвенность распознавания сплитов: порог 20% по дилюции — эвристика, а не факт
   корпоративного действия.
5. Отсутствие проверки знаков и коэффициентов ADR при наличии иностранного эмитента
   в списке наблюдения.
